# Hero animation: sources

The terminal animation at the top of the profile (`assets/hero-dark.svg`, `assets/hero-light.svg`, generated by `scripts/build_hero.py`) presents a real case rather than an illustration, so every line must stay traceable to a public record. This note lists those records as of 2026-10-07.

The fix shown is [WISE-API PR #325](https://github.com/WISE-Community/WISE-API/pull/325), "fix(security): re-check run ownership when batch resetting group passwords", authored by Isaries and merged on 2026-07-16. Its description states that the submitted group id was not checked against a run the teacher owns, so a teacher could reset the passwords of another teacher's students. The project builds with Maven (`mvnw package`, as the PR's testing section says), which is why the animation uses `./mvnw package` and not Gradle. The fix throws `NotAuthorizedException` from a form controller, so the animation deliberately avoids HTTP status codes.

"BUILD SUCCESS" before and after the fix reflects upstream CI: the `build` check run succeeded on the PR's base commit `0e7e3c06`, on its head commit `322325c6`, and on the merge commit `024707ca`.

The controller's test, `BatchStudentChangePasswordControllerTest.java`, exists in the repository but is listed in `pom.xml` under both the compiler's `testExcludes` and Surefire's `excludes` (lines 159 and 208 on `main` at the time of writing), so it is neither compiled nor run. The exclusion was introduced in commit `a191ab7d` on 2020-05-20 and was present at every spot-checked revision since, including the `pom.xml` in effect when PR #325 merged. The test itself contains only success-path cases (`testOnSubmit_success_1` to `_3`). The animation states the exclusion but, by choice, not its age or the success-only coverage, to keep the tone neutral toward the upstream project.

If any of these facts change upstream (for example the exclusion is removed, or the line numbers move), update `SCRIPT` in `scripts/build_hero.py`, rerun it, and update this note.
